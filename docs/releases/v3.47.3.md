# v3.47.3 — the plan now tells the truth about in-place installs

**(English / 中文 below)**

The installer's default folder is the folder you unzipped (since v3.47.2). This release makes the dry-run
plan say what it will actually do in that case, instead of claiming it is about to "create" a folder that
already exists and "copy sources" that are already there:

```
① 安装目录          沿用本目录（原地安装）
② 复制源码          跳过（源码已在本目录，不复制也不删除）
```

If you point it somewhere else with `--install-dir`, the plan still reads "create the install folder" and
"copy N items".

## Also in this release

- **A regression test that actually bites.** `tests/unit/install-behavior.test.mjs` gained 9 assertions,
  checked in both directions: no `--install-dir` ⇒ the default is the package folder and the plan says
  "in place"; an explicit `--install-dir` ⇒ "in place" must NOT appear. Reverting the default makes 3 of
  them go red; restoring it turns all 25 green.
- **A README sentence that had become wrong.** Both language halves used to say "**Do not** point it at
  the folder you unzipped" — true under the old default, backwards under the new one. It now says the
  opposite, and the example paths in the README are updated to 3.47.3.

Install: `cd /path/to/deepseek-harness-web-companion-3.47.3 && node bootstrap/install.mjs` for a dry run,
add `--apply` to really install. Requirements: macOS, Node 22+, Chrome.

# v3.47.3 — 原地安装的计划不再谎报动作（中文）

安装器的缺省目录从 v3.47.2 起就是"你解压出来的那个文件夹"。这一版让 dry-run 计划如实描述这种情况下
它要做什么 —— 而不是声称要"创建"一个已存在的目录、要"复制"本来就在位的源码。

用 `--install-dir` 指到别处时，计划仍然显示"创建安装目录"和"复制 N 项"。

## 同版其它内容

- **一条真会咬人的回归测试**：`tests/unit/install-behavior.test.mjs` 新增 9 条断言，**双向**校验 ——
  不给 `--install-dir` 时缺省值必须是本包目录且计划显示原地安装；显式给了 `--install-dir` 时
  **绝不能**出现"沿用本目录"。把缺省值退回旧写法，其中 3 条立刻变红；恢复后 25 条全绿。
- **README 里一句已经说反的话**：中英文两半原本都写着「**不要**装进你解压出来的那个文件夹」——
  在旧缺省值下是对的，在新缺省值下正好相反。现已改成相反的说法，示例路径也更新到 3.47.3。

安装：`cd /path/to/deepseek-harness-web-companion-3.47.3 && node bootstrap/install.mjs` 先看计划，
加 `--apply` 真装。前置：macOS、Node 22+、Chrome。
