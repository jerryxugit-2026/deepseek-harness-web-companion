# v3.48.0 — the wizard reports dependencies instead of installing them

**(English / 中文 below)**

The installer no longer downloads or installs anything. It checks your machine and prints a **dependency
report**: what is missing, where it belongs, and the exact command to copy. If a required dependency is
missing, it stops **before writing a single file**.

## Why this changed

It used to decide by itself and pull things in — including `npm install -g @deepseek-ai/dsh` when it did
not find `dsh`. On a real machine DeepSeek Harness was installed **from source**, and the check only ran
`command -v dsh`: it never saw that install and was about to add a second, global copy. Two DSH versions
on one machine, and no way for the user to tell which one runs. As the user put it: checking dependencies
in code and downloading them "looks clever, and is probably wrong".

## What it does now

```
 依赖怎么装（本程序不下载、不安装任何依赖；下面是可直接复制的命令）
   ✅ DeepSeek Harness（dsh 命令）  /Users/you/.local/bin/dsh (0.1.5-rc.2)
   ❌ 插件运行时依赖                你的 DSH 里缺 ws
        ↳ 在 DSH 安装目录里装：cd "/opt/homebrew/lib/node_modules/@deepseek-ai/dsh" && npm install ws
   ✅ esbuild（构建扩展用）         …/extension/node_modules/esbuild
```

- **Multi-source detection**: `--dsh <path>` (new, for source/custom installs) → `PATH` → npm global
  prefix and common locations. Every candidate found is printed.
- **Three kinds of dependency**, each with its own copy-paste command: DeepSeek Harness, the plugin's
  runtime packages, and `esbuild` (needed once to build the extension).
- **A missing required dependency stops the wizard before it writes anything** (exit code 2). The old
  order copied the sources first and only noticed the missing DSH at step 3, leaving a half-install.

## Install

```bash
cd /path/to/deepseek-harness-web-companion-3.48.0
node bootstrap/install.mjs          # dry run: machine check + dependency report, writes nothing
node bootstrap/install.mjs --apply  # asks before every step
```

First, install the two prerequisites yourself (the wizard tells you the exact command if one is missing):

```bash
npm install -g @deepseek-ai/dsh@0.1.5-rc.2        # version pinned — `latest` sub-packages are a stub
npm install --prefix "<the folder you unzipped>/extension" esbuild   # ~11 MB, once
```

Requirements: macOS, Node 22+, Chrome.

# v3.48.0 — 向导只报告依赖，不再替你装（中文）

安装器**不再下载、不再安装任何东西**。它检查你的机器，然后打印一份**依赖报告**：缺什么、装到哪、
可以直接复制的命令。关键依赖缺失时，它在**写任何一个文件之前**就停下来。

## 为什么改

它原来是"自己判断、自己去下"的 —— 包括找不到 `dsh` 时直接 `npm install -g @deepseek-ai/dsh`。
真实机器上那台 DSH 是**源码**形态装的，而检查只跑了一句 `command -v dsh`：既没看见那份安装，
还差点又装一份全局的 —— 一台机器两个 DSH，用户根本分不清跑的是哪个。用他的话说：
用代码检查依赖再去下载，「看起来聪明, 很可能不对」。

## 现在的行为

- **多源探测**：`--dsh <路径>`（新增，给源码/自定路径的安装用）→ `PATH` → npm 全局前缀与常见位置；
  找到的候选全部打印。
- **三类依赖**各带一条可复制的命令：DeepSeek Harness、插件的运行时包、`esbuild`（构建扩展用一次）。
- **关键依赖缺失 ⇒ 在写任何文件之前停下**（退出码 2）。旧顺序是先拷源码、到第 3 步才发现缺 DSH，
  留下一个跑不起来的半成品。

## 安装

```bash
cd /path/to/deepseek-harness-web-companion-3.48.0
node bootstrap/install.mjs          # dry run：体检 + 依赖报告，不写任何文件
node bootstrap/install.mjs --apply  # 每一步都先问你
```

先自己装两个前置（缺了向导会把确切命令打出来）：

```bash
npm install -g @deepseek-ai/dsh@0.1.5-rc.2        # 版本钉死 —— 它的 `latest` 子包是 stub
npm install --prefix "<你解压出来的那个文件夹>/extension" esbuild   # 约 11 MB，只需一次
```

前置：macOS、Node 22+、Chrome。
