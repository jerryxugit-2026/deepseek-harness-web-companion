# v3.49.0 — no more "all green while the old copy is the one running"

**(English / 中文 below)**

A machine can hold several copies of this plugin. The self-check used to guess which one you meant from
where the script you ran lives — so on a machine with an old copy mounted (`~/.dsh/plugins/...`, version
0.1.0) and a new copy in the project folder (3.48.2), the check reported **all green about the copy that
was not running**. That is a false green, and it was found by upgrading that very machine.

## What changed

1. **The install folder is now derived from the profile mount line** — the one place that records which
   copy DSH actually loads. Precedence: `--install-dir` > mount line > the package folder.
   `doctor --json` reports `installDirSource` (`arg` / `mount` / `package`) and the human output says
   where it came from.
2. **`/ag/ping` now reports which file the running plugin was loaded from** (`pluginEntry`), and a new
   hard criterion compares it with the mount line: *the plugin that is running == the one mounted*.
   When that cannot be judged (plugin not answering, plugin too old to report the field, no mount line)
   the criterion is a warning, never a green and never a red.

The protocol gained one optional field (schema, positive vector and generated validator are in sync);
payloads without it still validate.

## Install / verify

```bash
cd /path/to/deepseek-harness-web-companion-3.49.0
node bootstrap/install.mjs            # dry run: dependency report, writes nothing
node bootstrap/install.mjs --apply    # asks before every step
node bootstrap/doctor.mjs             # now prints where the install folder came from
```

After installing 3.49.0 you must **restart DSH once** for the new criterion to have data to compare (the
old plugin does not report the field) — the check says so instead of guessing.

# v3.49.0 — 不再出现"全绿但跑的是旧那份"（中文）

一台机器上可以有好几份本插件。自查原来是靠"你运行的那个脚本在哪个目录"来**猜**该查哪一份 —— 于是
在一台"挂载的是旧副本（`~/.dsh/plugins/...`，0.1.0）、项目目录里是新副本（3.48.2）"的机器上，
它会对着**没在跑**的那一份报全绿。这是假绿，而且正是在给那台机器升级时才发现的。

## 改了什么

1. **安装目录改为从 profile 挂载行反推** —— DSH 就是照那一行加载插件的，那是唯一真源。优先级：
   `--install-dir` > 挂载行 > 本包目录。`doctor --json` 会报 `installDirSource`
   （`arg` / `mount` / `package`），人类可读输出里也标出来源。
2. **`/ag/ping` 现在会报"运行的这份插件是从哪个文件加载的"**（`pluginEntry`），并新增一条硬判据：
   *正在运行的插件 == 挂载的那份*。判不了的时候（插件没应答 / 插件太旧没这个字段 / 没有挂载行）
   它是 ⚠️ —— 既不报绿也不报红。

协议只新增了一个**可选**字段（schema、正向量、生成的校验器都已同步）；不带它的旧载荷仍然合法。

## 安装 / 验证

```bash
cd /path/to/deepseek-harness-web-companion-3.49.0
node bootstrap/install.mjs            # dry run：依赖报告，不写任何文件
node bootstrap/install.mjs --apply    # 每一步都先问你
node bootstrap/doctor.mjs             # 现在会打印安装目录的来源
```

装完 3.49.0 后需要**重启一次 DSH**，新判据才有数据可比（旧插件不报那个字段）—— 自查会把这一点说出来，
而不是靠猜。
