# v3.47.2 — 装在你解压的那个文件夹里

**(English below / 中文在下面)**

The default install folder is now **the folder you unzipped** (it used to be `~/.dsh/plugins/...`).
Just press Enter at the first question and it installs where you are.

## Why this needed more than a one-line change

The copy step was "delete the destination, then copy the source over it". When the install folder *is*
the source folder, that deletes your unzipped package and then tries to copy from the path it just
deleted - i.e. it destroys the download. In-place installs now skip the copy entirely (the sources are
already where they belong), so the new default is safe.

## Install

```bash
cd /path/to/deepseek-harness-web-companion-3.47.2
node bootstrap/install.mjs          # dry run - prints the plan, writes nothing
node bootstrap/install.mjs --apply  # asks before every step
```

Press **Enter** at 「本程序安装到哪个目录？」 to accept the folder you are in, and Enter again for the
DSH data folder. Then `chrome://extensions` → Developer mode → Load unpacked → pick the
`extension/dist` folder inside that same folder.

**Requirements**: macOS, Node 22+, Chrome. No compiler, no Xcode.

# v3.47.2 — 装在你解压的那个文件夹里（中文）

缺省安装目录现在就是**你解压出来的那个文件夹**（原来是 `~/.dsh/plugins/...`）。
第一个问题直接回车，它就装在当前这个目录里。

## 为什么不是改一行就完事

原来的复制步骤是"先删掉目标、再把源码拷过去"。当**安装目录就是源码目录**时，它会先删掉你解压出来的包，
再试图从刚被删掉的路径复制 —— **把下载的包毁掉**。现在原地安装**整段跳过复制**（源码本来就在位），
所以新的缺省值才是安全的。

## 安装

```bash
cd /path/to/deepseek-harness-web-companion-3.47.2
node bootstrap/install.mjs          # dry run：只打印计划，不写任何文件
node bootstrap/install.mjs --apply  # 每一步都先问你
```

在「本程序安装到哪个目录？」处按**回车**＝就是当前这个文件夹；DSH 数据目录再按一次回车。
然后 `chrome://settings`… 不对，是 `chrome://extensions` → 开发者模式 → 加载已解压的扩展程序 →
选**同一个文件夹**里的 `extension/dist`。

**前置**：macOS、Node 22+、Chrome。不需要编译器、不需要 Xcode。
