# v3.48.1 — fixes from the adversarial review of v3.48.0

**(English / 中文 below)**

Three MAJOR findings from an independent review of v3.48.0, each reproduced before fixing:

1. **`--dsh <wrong path>` silently discarded a working DSH on `PATH`.** `node bootstrap/install.mjs
   --dsh /tmp/nope/dsh` reported only "the path you named does not exist" (the `PATH` install appeared
   nowhere in the output) and blocked the whole run. Now every candidate found is printed with its
   source, the first **existing** one is used, and it says plainly: *you named X, it is not there, I am
   using Y instead*.
2. **Two holes in the tests.** `[].every(...)` is always true, so the "no npm install happened"
   assertion also passed when the probe never ran; and the fake `npm` only intercepts an npm invoked by
   name through `PATH`. Now the log must be **non-empty**, and the whole sandbox is snapshotted before
   and after: nothing may be created except npm's own cache directory.
3. **`--yes` skipped blockers, so a known precondition failure exited 3 ("failed midway") instead of
   2 ("precondition not met").** `--apply --yes --install-dir /System/...` proved it (`EPERM` at step 1).
   `--yes` means "do not ask me", not "ignore blockers" — it now exits 2 and states that no file was
   written.

Also: `fix` and `command` now have distinct jobs (the report prints the copy-paste line as `$ …`), the
esbuild command points at the `extension` folder inside the package (the install folder may not exist
yet), `which()` no longer interpolates into a shell string, and the README says the one thing the wizard
does write for a dependency: a symlink to an `esbuild` you already have.

**An honest correction**: v3.48.0's notes claimed that disabling the dependency gate turns the tests red.
After fix 3 that is no longer true — there are now two gates and either one alone enforces the guarantee.
Both are kept (defence in depth) and a deliberately-labelled wiring assertion now guards the dependency
gate itself, so removing it does redden a test again.

Install: download `Source code (zip)` for v3.48.1, then `node bootstrap/install.mjs` (dry run) inside the
unzipped folder. Requirements: macOS, Node 22+, Chrome, plus DeepSeek Harness and esbuild — the wizard
tells you the exact command for anything missing.

# v3.48.1 — 复核 v3.48.0 之后的修正（中文）

针对 v3.48.0 的独立复核提出的三条 MAJOR，逐条**复现后才修**：

1. **`--dsh <错路径>` 会把 `PATH` 上可用的 DSH 静默丢弃**：报告只写"你点名的路径不存在"（`PATH` 上那份
   一个字都没提），整轮被阻断。现在会把找到的候选**全部**连来源一起打印，采用第一个**存在**的，
   并明说"你点名的 X 不存在，我改用 Y"。
2. **测试有两个洞**：`[].every(...)` 恒真 ⇒ 探测根本没发生时"没有 install"也是绿的；假 npm 只挡
   "经 PATH 按名字调的 npm"。现在要求记账**非空**，并对整个沙箱做前后快照：除 npm 自己的缓存目录外
   不许新增任何文件。
3. **`--yes` 会跳过阻断项**，于是"安装目录不可写"这种已知前置条件失败会一路 mkdir 到 `EPERM`，
   退 **3（中途失败）** 而不是 **2（前置条件不满足）**。`--yes` 是"别问我"，不是"别管阻断项" ——
   现在退 2 并声明没有改动任何文件。

另外：`fix` 与 `command` 各司其职（报告用 `$ …` 单独打印可复制的命令）；esbuild 的命令指向**包内**的
`extension`（安装目录那时可能还不存在）；`which()` 不再把命令拼进 shell 串；README 点明依赖层唯一的
写入是"复用你已有的 esbuild 时建一个符号链接"。

**一处诚实更正**：v3.48.0 的说明里我写过"禁用依赖门禁 ⇒ 测试变红"。修完第 3 条之后这句话不再成立 ——
现在有两道门，任何一道单独都能保证"缺依赖不写文件 + 退 2"。两道门都保留（纵深防御），并给依赖门补了
一条明确标注为接线检查的断言，所以现在删掉它**确实会**让测试变红。

安装：下载 v3.48.1 的 `Source code (zip)`，解压后在目录里跑 `node bootstrap/install.mjs`（dry run）。
前置：macOS、Node 22+、Chrome，外加 DeepSeek Harness 与 esbuild —— 缺什么向导会给出确切的安装命令。
