## 0. 一分钟版

```bash
# 1. 先看它打算做什么（默认 dry-run，一个字节都不动）
node bootstrap/install.mjs

# 2. 看着没问题了，真装（每一步都会问你一次）

# 3. 装完随时自查

## 1. 装完你会得到什么

| 东西 | 落在哪 | 说明 |
|---|---|---|
| 桥接插件（宿主端 + 页面端） | `<安装目录>/dsh-plugin/` | DSH 进程内的插件，负责 `/ag/*` 路由、落盘、`browser_*` 工具 |
| 扩展构建产物 | `<安装目录>/extension/dist/` | **在你自己机器上现场构建**，端口与配对 key 都按你的环境烤进去 |
| 原生拉起器 | `<安装目录>/native-host/` | 让 Chrome 能在 DSH 没跑时把它拉起来 |
| Chrome 清单 | `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.dsh.web_companion.json` | 允许你的扩展叫起本地程序 |
| 配对钥匙 | `~/.dsh/dsh-web-companion.json` | 扩展 ↔ 插件之间的共享密钥（**幂等：已存在就复用，不轮换**） |
| 插件挂载行 | `~/.dsh/profiles/web/cordis.patch.yml` | 告诉 DSH 去加载插件（**只改我们这一条，改前备份**） |

默认安装目录：**你解压出来的那个文件夹**（直接回车即用它）；DSH 数据目录默认 `~/.dsh/`。
**不给 `--install-dir` / `--dsh-home` 时，向导会在打印计划之前分别问你这两件事**（直接回车＝用默认值，`~/…` 会展开）。
管道/CI 与 `--yes` 下**绝不阻塞**，直接用默认值。

## 3. 引导程序会做哪 10 步

每一步都会先打印"要动什么"，然后**单独问你一次**（`--yes` 才批量同意）。
不在终端里跑（管道/CI）且没给 `--yes` 时，**所有询问一律按"否"处理** ——
于是它只会打印计划，不会自作主张。

| 步 | 做什么 | 会碰哪些文件 |
|---|---|---|
| 1 | 创建安装目录 | `<安装目录>` |
| 2 | 复制**我们自己的源码** | `<安装目录>/…`（**不含 `node_modules`、不含 `dist`**） |
| 3 | 接上插件依赖（**链接**到你的 DSH，不下载） | `<安装目录>/dsh-plugin/node_modules/…`（符号链接） |
| 4 | 准备 `esbuild`（**向导不再下载**；缺了在依赖报告里给命令） | `<安装目录>/extension/node_modules/` |
| 5 | 生成/复用配对钥匙 | `~/.dsh/dsh-web-companion.json`（+ `.bak-before-install`） |
| 6 | 现场构建扩展产物并自证端口 | `<安装目录>/extension/dist/` |
| 7 | 安装 native messaging host | Chrome 清单 + `<安装目录>/native-host/run-host.sh` |
| 8 | 写插件挂载行 | `~/.dsh/profiles/web/cordis.patch.yml`（+ `.bak-before-companion`） |
| 9 | 引导你申请并粘贴 DeepSeek API key | `~/.dsh/.credentials.yaml`（+ `.bak-before-apikey`） |
| 10 | 打印 Chrome 扩展的手装步骤，等你确认 | 只打印，不动文件 |
| 11 | 复检（DSH 应答 / 已配对 / 产物端口 / 扩展连通） | 只读 |

## 4. 依赖为什么是"链接"而不是"下载"

> **2026-09-13 变更：向导不再下载、不再安装任何依赖。**
> 用户实测后定调：「我们用代码去检查依赖, 然后去下载, 看起来聪明, 很可能不对」——
> 他那台机器上 DSH 是**源码**形态装在 `/Volumes/Ex/ai_workspace/deepseek-harness`（没有 `node_modules`、
> 根包名是 `@deepseek-ai/dsh-root`），而旧探测只做 `command -v dsh`，一个字都没提，还准备再装一份全局的。
>
> 现在向导的行为：
>   1. **多源探测**：`--dsh <路径>` 点名 → `PATH` → npm 全局前缀与常见位置；候选全部打印；
>   2. **依赖报告**：缺什么、装到哪、**可直接复制的命令**（DSH / 插件依赖 / esbuild 三类）；
>   3. **缺关键依赖 ⇒ 在写任何文件之前停下**（退出码 2）。旧顺序是第 1/2 步先把源码拷了，
>      到第 3 步才发现缺 DSH，留下一个跑不起来的半成品。
>
> 你自己要跑的命令（缺什么跑什么）：
> ```bash
> npm install -g @deepseek-ai/dsh@0.1.5-rc.2                                  # DeepSeek Harness 本体
> cd "<你的 DSH 安装目录>" && npm install ws                                  # 插件的运行时依赖（若报告说缺）
> npm install --prefix "<安装目录>/extension" esbuild                          # 构建扩展用（若报告说缺）
> ```

这是本安装器最关键的一个设计，来自**读一个真实可用的部署**而不是猜：

插件的 `node_modules/` 里**没有真实安装**任何包，而是三个**符号链接**指向你那份 DSH 自带的子包：

```
dsh-plugin/node_modules/@deepseek-ai/dsh-tools       -> <DSH 安装根>/node_modules/@deepseek-ai/dsh-tools
dsh-plugin/node_modules/@deepseek-ai/dsh-credentials -> <DSH 安装根>/node_modules/@deepseek-ai/dsh-credentials
dsh-plugin/node_modules/ws                           -> <DSH 安装根>/node_modules/ws
```

好处有四条，每条都是实测过的：

1. **版本永远一致** —— 插件跑在 DSH 进程里，用的就是 DSH 自己那份子包。
   你把 DSH 从 0.1.2-rc.1 升到 0.1.5-rc.2，插件**什么都不用做**就跟着走了。
2. **不用下载** —— DSH 装好就自带这三个包。
3. **绕开 peer 依赖地狱** —— 单独 `npm install @deepseek-ai/dsh-tools@0.1.5-rc.2` 会
   `ERESOLVE` 失败（它 peer 依赖 `dsh-llm`、`cordis`、`dsh-agent` 等 9 个包）；
   而链接进 DSH 的树里，peer 天然齐全。
4. **升级 DSH 不必重装插件。**

**不要用 `latest` 装 DSH 或它的子包**：实测 `@deepseek-ai/dsh-tools` 的 npm `latest`
是 `0.0.1-rc.1`（一个 stub）。引导程序会**钉版本**，并把"用哪个版本"作为显式参数。

## 5. DeepSeek API key 怎么弄

引导程序第 9 步会把步骤打在屏幕上，并让你**粘贴**（终端里不回显，避免 key 留在滚动缓冲里）：

1. 打开 <https://platform.deepseek.com/> 注册 / 登录；
2. 左侧「API keys」→「Create new API key」；
3. 复制那串 `sk-` 开头的字符串（**只显示一次**），粘进引导程序。

写进 `~/.dsh/.credentials.yaml` 的 `refs.DEEPSEEK_API_KEY`。

**它只改这一行。** 那个文件里还住着别的 key，以及一条
`records.client-connection/browser-session` 记录（**插件签发登录 cookie 就靠它**）。
引导程序做的是**定点改写 + 先备份**，绝不整体重写。留空则跳过，不动这个文件。

> 为什么引导程序要自己写这个文件：DSH **没有**自带的设置 key 的命令
> （实测 `dsh --help` 只有 `web` 与 `plugin`）。

## 6. Chrome 扩展怎么装（这一步只能你手动做）

1. 地址栏输入 `chrome://extensions`
2. 右上角打开**开发者模式**
3. 点**加载已解压的扩展程序**
4. 选择 `<安装目录>/extension/dist`
5. 点浏览器工具栏里的图标打开侧边栏

装好后回到引导程序按回车，它会复检。

> **为什么不能全自动**：Chrome 不允许静默安装扩展（137+ 已移除 `--load-extension`）。
> 本项目的自动化探针走 CDP 的 `Extensions.loadUnpacked`，那是**测试通道**，不是给用户装扩展用的。

## 7. 装完怎么确认真的通了

```bash
node bootstrap/doctor.mjs          # 人看的输出
node bootstrap/doctor.mjs --json   # 机器可读（贴 issue 用）
```

它判四件事，其中**三条是硬判据**（决定退出码）：

| 判据 | 类型 | 含义 |
|---|---|---|
| DSH 在端口上应答 | 硬 | 起没起、端口对不对 |
| 插件已加载并配对（`paired`） | 硬 | 挂载行与配对文件是否对得上 |
| 扩展产物端口 == 真实配对端口 | 硬 | 防止"产物被烤进别的端口"这类事故 |
| 扩展连通 | **软（代理判据）** | 看的是 `connectedClients`（DSH **页面半**的连接数） |

**关于最后那条，必须诚实说明**：扩展是 Chrome 里的东西，它不主动连上来，**外面就看不见它**。
本插件当前也没有暴露"扩展的 `/ag/agent` 通道数"。所以这一条是**代理判据** ——
侧边栏一打开，iframe 里的 DSH 页面半就会连上，`connectedClients` 因此 >0。
它**不参与总判定**（`0` 不代表扩展没装，只代表你现在没开侧边栏），并会告诉你下一步怎么做。

## 8. 卸载

```bash
node bootstrap/uninstall.mjs            # 先看要卸什么（dry-run）
node bootstrap/uninstall.mjs --apply    # 真卸
```

只反向移除**属于我们的东西**：

- 摘掉 profile 里我们那一条挂载（先备份）；
- 删掉 Chrome 的 native messaging 清单；
- 删掉安装目录（想留着加 `--keep-files`）；
- **配对钥匙默认保留**（删了会连带影响重装后的配对），要清加 `--purge-pairing`；
- **API key 永不删** —— 那是你的凭据，跟本插件无关。

## 9. 出问题怎么办

| 现象 | 原因 / 怎么办 |
|---|---|
| `❌ Node.js ≥ 22` | 去 <https://nodejs.org> 或用 nvm/fnm 装；**引导程序不代装 Node**（要系统权限） |
| `⚠️ 端口被占用，但应答的不是本插件` | `lsof -nP -iTCP:3080 -sTCP:LISTEN` 看是谁；或换端口 `--port 3099` |
| `⚠️ 找不到 Chrome 的配置目录` | 先装 Chrome 并**启动过一次**，再重跑 |
| 装完面板连不上（`E_EXT_OFFLINE`） | 先 `node bootstrap/doctor.mjs` 看是哪一条；常见是扩展没加载，或**改了端口没重建**（重跑第 6 步） |
| 报"扩展 ID 被改掉了"并停下 | 这是**守卫**在拦一次真实事故：安装过程换了扩展 ID，会让 Chrome 里已装的扩展、配对文件、native host 清单三者互相不认。按提示用 `.bak-before-install` 回滚配对文件后重试 |
| `dsh` 版本与我们验证过的不同 | 引导程序会**警告但不阻断**（实测跨小版本可用）。遇到怪问题先换回验证过的版本 |
| 想回滚这次安装 | 挂载：`cp ~/.dsh/profiles/web/cordis.patch.yml.bak-before-companion ~/.dsh/profiles/web/cordis.patch.yml`；配对：`cp ~/.dsh/dsh-web-companion.json.bak-before-install ~/.dsh/dsh-web-companion.json` |

## 10. 安全与可回滚（引导程序遵守的规矩）

1. **默认 dry-run**：不加 `--apply` 只打印计划。
2. **每一步单独确认**（`--yes` 才批量）；非交互环境一律按"否"，**绝不阻塞、绝不自作主张**。
3. **关键步骤失败就当场停**，并且**不写 DSH 挂载** —— 免得把"装到一半"变成"原来的也不能用"。
4. **写挂载之前先自证**：真的 `import()` 一次安装目录里的插件，确认依赖解析得开。
5. **改任何配置都先备份**，并打印回滚命令。
6. **只动自己的东西**：别人的 `semble` / `codegraph` 条目、别的 key、浏览器里别的原生程序清单，
   一概不碰（有单测逐字节断言）。
