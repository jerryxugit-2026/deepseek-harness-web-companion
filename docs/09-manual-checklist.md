# 人工验收清单（有头 Chrome）

自动化能证明的都证明了（见 `docs/reviews/*.json`）。**这份清单只列自动化做不了的事** —— 需要真实用户手势、真实弹窗、真实判断的地方。每项都写了"失败时怎么办"。

前置：`dsh web` 在跑、扩展已加载/刷新、侧边栏能打开、`http://127.0.0.1:<port>/ag/ping` 返回 `paired: true`。

## A. 授权弹窗三分支（唯一必须由人手点的路径）

`chrome.permissions.request` 必须由用户手势触发（实测：无手势会抛 `must be called during a user gesture`）。

1. **允许**：面板点「Attach 网页」→ 首次会弹「读取所有网站」→ 点**允许** → 状态栏出现「已附加：@网页捕获/…」。
   - 失败：状态栏显示"当前网页未获授权" → 说明弹窗被拒，重试并注意点是。
2. **拒绝**：再点一次，弹窗里点**取消** → 状态栏停在"未授权：可在目标网页点一次扩展图标（临时授权）后重试"，**不应**有半截文件落盘。
3. **撤销**：`chrome://extensions` → 本扩展 → 站点访问权限 → 改为「点击时」→ 回到面板抓一个**未在 host 权限里**的站点（例如 `https://example.com`）。
   - 期望：要么走 `activeTab`（先在目标页点一次扩展图标），要么给出可操作提示；**不允许静默失败**。

## B. 「正在调试」横幅与浏览器控制开关

4. 面板勾选「浏览器控制」→ 面板状态栏提示"已开启…"。
   - **横幅是"每次调用时短暂出现"，不是常驻**（2026-09-12 人工验收实测，见 `docs/reviews/manual-acceptance-2026-09-12.md` B4）：
     开关只是**许可**，真正的 attach 发生在每次浏览器操作里（`ops/debugger.js#withDebugger`：attach → 执行 → `finally` 里 detach），
     所以「正在调试此浏览器」横幅只在一次调用进行中可见（整页截图约 1 秒、AX 树约 0.1 秒），之后自动消失。
   - 想亲眼看到：让模型连发几次整页截图，盯着目标标签页顶部。
5. 让模型调用一次写操作（或手动触发 `browser_click`）：应弹出 **DSH 审批请求**。
   - **前置**：`/ag/control` 要么回 `approvalMode: "ask"`（会真的弹提示），要么回 `policy-never`（本会话审批提示被关掉）。
     后者**不会**有弹窗，写操作会被插件当场拒绝，理由写的是"审批策略是 never"（v3.41 起如此；以前它会说"用户拒绝了"，而没有人被问过）。
   - 批准 → 页面真的变化；拒绝 → 工具返回 `denied` 且**页面不变**。
6. 取消勾选「浏览器控制」→ 再让模型调一次 `browser_ax`/整页截图：应被**拒绝**（`E_NO_PERMISSION`，提示先打开开关），且不会有任何 attach（插件在关开关时 `detachAll` 兜底释放残留占用）。
7. ~~打开 DevTools 再点「浏览器控制」→ 期望 attach 失败~~ **这条期望已作废（2026-09-12 实测）**：
   真机 Chrome 150 上，DevTools 打开着时本扩展 `chrome.debugger.attach` **照样成功**（连测两次，`browser_ax` 都返回了 999 节点的树）。
   多调试器并存是新版 Chrome 的行为。`E_TARGET_BUSY` 的真实触发是**另一个扩展**占着该目标
   （以及同一扩展重复 attach —— 后者由 `probe:m3-debugger` 的 `secondAttach` 记录在案：Chrome 原文 `Another debugger is already attached to the tab with id: …`）。
   要验这条得装第二个用 debugger 的扩展，本清单不再要求。

## C. 「看左边」的自然使用

8. 打开任意网页 → 侧边栏 DSH 输入框写「看左边」→ 期望：① 面板状态栏「已附加：…」② 输入框里那句话**下面**多出一行 `@网页捕获/….md` ③ 上方出现胶囊 ④ 工作区多一个 `.md`。
9. 把那句话删掉，再写一次「看左边」→ 应再次触发（同一会话内连续可用）。
10. 关掉侧边栏，写一次「看左边」（用另一个 DSH 窗口/标签页）→ 再打开面板 → 期望**补发一次**抓取（意图队列生效，`reason: queued`）。

## D. 抓取质量判断（机器判不了"这份是不是有用"）

11. 选三个你日常真的会抓的站点（文档站 / 新闻 / 内部系统），各抓一次，检查：
    - 正文完整（没有把主内容当噪音删掉）；
    - 顶部没有导航残留（面包屑、分类 chip、"Read more"）；
    - 代码块与列表结构正确；
    - 相对链接已绝对化（能点开）。
12. 若某站点被误删内容：记录站点 + 现象，并临时关掉对应开关（`stripChipRows` / `stripActionLabels` / `stripTrailingMeta` / `stripPlaceholderAnchors`）确认是它干的 —— 这能直接给出该站点的规则修正依据。

## E. 自动拉起与保留策略

13. 退出 `dsh web`（`lsof -ti :3080 | xargs kill`）→ 关掉侧边栏再打开 → 期望 native host 自动拉起（`~/.dsh/logs/dsh-web-companion-host.log` 有 `ensure-dsh → started=true`）。
14. 保留策略现场验证：在 `<workspace>/网页捕获/` 放一个**你自己命名**的文件，再抓一次 → 你的文件必须还在；把某个抓取文件的 mtime 改成 25h 前再抓一次 → 它应被删除。

## 记录方式

每项结果写进 `docs/reviews/manual-acceptance-<日期>.md`：项目号、结果（✅/❌）、观察、截图或日志片段。❌ 的项按 AGENTS.md 的约定处理：先分类（权限 / 平台限制 / 逻辑缺陷），再决定修法；平台限制要明说绕不开。
