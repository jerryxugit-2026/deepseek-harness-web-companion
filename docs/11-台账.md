## 7. 与设计不同的实现方式（逐条说明为什么）

| 改动 | 设计原样 | 实际做法 | 为什么 |
|---|---|---|---|
| 扩展语言与构建 | TypeScript + Vite | JavaScript + esbuild | 更快更少依赖；代价是少了类型检查，改为靠"探针 + 契约测试"兜底 |
| `debugger` 权限 | 可选权限、用时申请 | **必需权限 + 运行期开关 + 逐次审批** | Chrome 明确拒绝把它列为可选（实测报错），否则能力直接消失 |
| 「看左边」最后一跳 | 设计只写到"嗅探 + 发 intent" | 补了 `/ag/agent` 上传"抓取请求" + 未连上时排队、连上后补发 | 不补这一跳，意图到插件就断了（面板关着时也不丢） |
| 写操作开关 | 只能改配置文件（要重启 DSH） | 新增 `POST /ag/control`，面板上一个开关，**点一下即时生效** | 否则安全默认等于功能永久不可用 |
| 抓取文件清理 | 设计未提 | **每次抓取后清掉 24 小时前、本插件命名**的文件 | 你提出：目录会无限膨胀；且它同时是 AI 的输入（上下文成本） |
| 抓取噪音清理 | 设计只有"正文抽取" | 四条可独立开关的启发式（分类标签行 / 操作标签 / 尾部统计 / 占位空链接） | 真站点实测：正文区里混着界面残留 |
| 整页截图 | 设计无上限 | 超过 12000 像素高就裁剪，并如实回报"被裁剪了" | 否则超大图会被丢弃 → 工具直接失败（现在变成"带说明的成功"） |
| 胶囊（页面上的小标签） | 设计想用 DSH 插槽 | 先做了 DOM 版，v3.33 改成**插槽版**，DOM 版留作兜底 | 插槽版让样式与生命周期跟 DSH 一致 |
| 真模型端到端 | 设计列为"需人工" | 做成自动脚本（E2E-16） | 把"只有人能验"的一环变成可回归 |
| 质量审计工具 | 设计无 | `npm run audit:captures` + 抓取文件记录构建版本 | 让"质量有没有退步"有数字可看，而不是凭感觉 |

## 8. 本会话修掉的真缺陷（都是跑出来的，不是设计出来的）

1. **插件把工具调用发给"僵尸连接"**：连接断开时该清的那段代码被误删，导致死连接一直留着 —— 它们收得到广播心跳、却吞掉工具调用，AI 看到的是"扩展超时"（排查方向被完全带偏）。已修复 + 新增单测。
2. **校验器返回值被误读**：导致「看左边」整条链路**静默失效**（不报错、就是不动）。已修复 + 加了自动拦截规则。
3. **把"自己家的页面"当抓取目标**：面板作为普通标签页打开时，抓取必然失败并给出误导性提示。已修复（跳过自身页面）。
4. **引用（blockquote）生成非法 Markdown**：内容没丢但格式语义丢了。已修复。
5. **`Load more` 这类按钮没被清理**：真站点上残留。已修复。
6. **截图工具忽略调用者的"整页"标志**：请求视口却给整页图（慢 20 倍）。已修复。
7. **没划选却点「Attach 选区」会静默抓整页**：已改为明确拒绝。
8. **保留策略不认截图命名**：截图目录本来会无限膨胀。已修复。
