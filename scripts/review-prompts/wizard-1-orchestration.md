# Prompt：安装/升级向导（片 1／共 3）—— 编排、幂等、假 dry-run、失败语义

你是本机的一名资深代码审查员。下面给你一个**已经实现、并且自称"多轮实测过"的终端安装向导**的一部分源码。
请审查**代码本身**，不要把注释里的自我评价当成事实，也不要复述文档结论。

## 这是什么程序（先看，避免误读）

`dsh-web-companion` = Chrome MV3 扩展 + DSH（DeepSeek Harness）进程内插件的组合。
插件跑在 **DSH 进程内部**（cordis 插件，靠 `~/.dsh/profiles/web/cordis.patch.yml` 里的一行被挂载），
提供 `/ag/*` 路由与 `browser_*` 工具；扩展提供侧边栏与抓取。

**本次审查对象只有 `bootstrap/` 这个终端引导程序**（无 GUI，纯 Node，macOS 优先）。
它要做的事：把仓库源码铺到用户的安装目录 → 检测并按需安装依赖 → 生成配对钥匙 → 构建扩展产物 →
写 Chrome native messaging 清单 → 把插件挂载行插进用户的 DSH profile → 把 DeepSeek API key 写进凭据文件 →
指导用户去 `chrome://extensions` 加载扩展 → 最后做一次健康复检。

用户对它的**硬约束（原话；逐条都要成立）**：

1. 「依赖程序都是用引导程序下载, 并不在我们打包的安装程序里, 不然会很重」——发行包只含我们自己的源码，不含 `node_modules`、不含预构建的 `dist`。
2. 「用户的系统我们暂时不考虑 windows 系统, 只考虑 mac」——Windows 分支可以不存在，但**不许假装成功**。
3. 「安装每一个依赖, 都需要用户确认一下」——每一处会动磁盘/装东西的动作都要先问。
4. 「引导程序不需要做 GUI 的, 一个终端界面的程序就可以」。
5. 「默认只打印'我打算改哪些文件', 不动真格」——不加 `--apply` 必须**一个字节都不动**。
6. 「如果用户的电脑上没有安装 DeepSeek harness」——要先装 DSH 本体，再从它里面链接插件依赖。
7. 「把安装向导程序和升级向导程序合一」（**新要求，可能还没实现**）：先判断本机装没装、依赖全不全；装了要比版本；版本旧要能升级。

## 你要找什么（按优先级）

### A. 假 dry-run（最严重）

`--apply` 缺席时**真的**一个字节都没写吗？逐条追 `mkdirSync` / `cpSync` / `rmSync` / `writeFileSync` /
`copyFileSync` / `symlinkSync` / `spawnSync` —— 每个调用点是否都在 `DRY_RUN` 分支保护下？
有没有"看着像只打印、其实已经落盘"的路径（先建目录、先写临时文件、先备份、先 `npm install`）？
`run()` 之外还有没有绕过它的直接 `spawnSync` / `execFileSync`？

### B. 编排、幂等与失败语义

- **重复跑**会怎样？每一步"要不要做"的判据是什么（存在性？内容比对？）——有没有"文件存在就当它是对的"
  这种**假幂等**（内容已经变了却跳过）？`rmSync` + `cp` 这类破坏性动作有没有先确认？
- **中途失败**（用户在某个 `confirm` 按 n、外部命令非零退出、npm 断网）之后的状态：写了一半的安装目录会怎样？
  下次重跑能不能自愈？"失败就停"的 `must()` 之类是否为**每一条**外部命令都覆盖了？没有覆盖的那些失败后会怎样？
- 步骤之间的**顺序依赖**是否真实成立（例如第 6 步构建扩展之前，配对钥匙与端口是否一定已经写好）。
- **退出码**：成功 / 失败 / 用户取消 分别是什么？自动化调用方能不能分辨？
- `process.exit()` 的调用点有没有在 stdout 还没 flush 时就把进程杀掉（管道里会丢输出）？
- `w.pause()` 的返回值被用在哪里？非交互时它直接返回 false —— 那条路径会不会**静默跳过**某个关键验证？

### C. 硬编码

端口、路径、版本号、目录名、"装哪个包"、超时被写死在多处且不一致（改一处漏一处）；
应该来自单一真源却各写一份的地方。特别看 `--dsh-version` 的默认值从哪来、`DEFAULT_PORT` 之类常量有几份。

### D. 装/升级合一：差距分析（**只列障碍，不要给设计方案**）

按用户第 7 条要求，现在的代码离"能当升级向导"还差哪些**具体的**东西？例如：怎么判断本机已装？
"本机版本"和"远端版本"分别从哪里取？（注意 `package.json` 的 version、CHANGELOG 里的 v3.x、扩展 manifest
的 version 目前**不是同一个数**。）升级时哪些文件必须重建、哪些必须保留（配对钥匙、用户改过的 profile）？
逐条给 `文件:行号` 证据。
