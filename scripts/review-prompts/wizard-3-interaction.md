# Prompt：安装/升级向导（片 3／共 3）—— 交互、预检与"健康判定"（假绿重灾区）

你是本机的一名资深代码审查员。下面给你一个**已经实现、并且自称"多轮实测过"的终端安装向导**的一部分源码
（交互层 + 预检 + 健康判定），外加它自己的单元测试。请审查**代码本身**，不要把注释里的自我评价当成事实。

## 这是什么程序（先看，避免误读）

`dsh-web-companion` = Chrome MV3 扩展 + DSH（DeepSeek Harness）进程内插件的组合。
终端引导程序 `bootstrap/` 负责装它：铺源码 → 装依赖 → 生成配对钥匙 → 构建扩展产物 →
写 Chrome native messaging 清单 → 插插件挂载行 → 写 API key → 指导用户去 `chrome://extensions` 加载扩展
→ **最后做一次健康复检**（这一步就是本片的核心材料之一）。

用户对它的硬约束（原话）：

1. 「安装每一个依赖, 都需要用户确认一下」——会动磁盘的动作都要先问。
2. 「默认只打印'我打算改哪些文件', 不动真格」——不加 `--apply` 时不写任何东西。
3. 「引导程序不需要做 GUI 的, 一个终端界面的程序就可以」。
4. 「引导程序需要告诉用户怎么申请 DeepSeek API key, 然后让他可以把 Key 贴进来」。
5. 「用户安装完 chrome 扩展以后, 在引导程序选择安装完成。这时候引导程序要检测所有的依赖, chrome 扩展是否都健康运行」。

**本片材料**：`bootstrap/lib/wizard.mjs`（终端问答）、`checks.mjs`（预检）、`probe.mjs`（探测）、
`health.mjs`（健康判定）+ 它们的三份单测。片 1（编排入口）与片 2（路径/接线）不在你范围内。

## 你要找什么（按优先级）

### A. 假绿（本片最重点，逐条追到底）

这个程序的价值全在"它说的话是不是真的"。请专门找**"看起来通过、其实是假的"**：

- `checks.mjs`：每个 check 在什么情况下会**误报通过**？例如目录"可写"是怎么判的（只看存在？只看权限位？
  真写一个临时文件了吗）？端口"空闲"是怎么判的（连不上就算空闲？那防火墙/别的服务占用会怎么表现）？
  `which()` 找到的是一个同名但不相干的程序时会怎样？把"探测不到"当成"通过"的分支在哪？
- `probe.mjs`：`pingPlugin` 的解析逻辑 —— 超时 / 非 JSON / HTTP 非 200 / 连上的**不是我们的服务** /
  `paired:false` / `keyConfigured:false`，每种情况分别返回什么？调用方有没有把其中某种当成"已配对"？
  `portListening` 与 `pingPlugin` 结论矛盾时，判定以谁为准？
- `health.mjs`：`evaluateHealth` / `overallOk` / `pendingHard` 的软/硬判据划分 —— 有没有把**真实的失败**
  标成 `soft`，于是总判定照样"通过"？反过来有没有把"探测不到"当成硬失败从而误报装坏了？
  `distOk === null` 那一支（没有产物脚本时）到底算通过还是失败？`renderHealth` / `renderChecks` 的渲染
  是否与判定**一致**（判定失败却渲染成 ✅、或反之）？渲染的行数与判定数组长度是分别算的还是同源？
- 三份单测：断言是否可能因为**空数组 / `undefined` / 默认值 / mock** 而恒真？有没有"只断言不抛异常"、
  "只断言数组存在"、"只断言 length > 0"这类空断言？有没有断言调用的是**测试专用 hook**，
  而真实用户路径走另一条？有没有为了绿灯把期望值改成了实现当前值？

### B. 交互安全（`wizard.mjs`）

- **非 TTY / 管道 / CI 下绝不阻塞**（注释声称如此）：逐分支验证。`--yes` 的语义边界是什么？
- 反过来：**该问的没问**。有没有会动磁盘的动作被放在"不问"的分支里（例如默认值就是"做"）？
  `confirm()` 的默认是 No —— 那么"用户一路回车"会发生什么？会不会出现"什么都没装，但最后打印成功"？
- `secret()`（读 API key）：不回显、不落屏幕滚动缓冲、Ctrl-C / EOF / 粘贴多行时的行为；
  key 会不会被写进日志、审计、或错误消息里？
- `pause()` 的返回值有没有被调用方**忽略**（非交互时返回 false ⇒ 后续步骤会不会静默跳过）？

### C. 硬编码与漂移

端口默认值、超时值、判据文案、退出码、`3080` 这个数字在几个文件里各写一份？
判定逻辑里有没有把某个"文案字符串"当判据用（改文案就改行为）？
