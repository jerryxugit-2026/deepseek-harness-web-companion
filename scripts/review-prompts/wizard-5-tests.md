# Prompt：审查**刚补的一批测试改动**（行为测试 + 修无效断言 + 去硬编码）

你是本机的一名资深代码审查员。下面给你 **① 这批测试改动的 diff**（`/tmp/wc-changes-tests.patch`，权威的"改了什么"）
与 **② 改动后的完整文件**。

## 背景

`bootstrap/` 是这个项目的终端安装引导程序（Node，**只支持 macOS** —— 用户明确要求，
"Windows/其它平台没实现"**不要**当缺陷报；但"非 mac 上假装成功"算缺陷）。

用户的硬约束里最要紧的一条是：**「默认只打印'我打算改哪些文件', 不动真格」**（不加 `--apply` 时一个字节都不许动）。

**这批改动只动测试与 `package.json`**，声称做的是：

1. **新增 `tests/unit/install-behavior.test.mjs`**：原有 5 个引导程序单测**全部**只测 `bootstrap/lib/*`
   的纯函数 ⇒ 上面那条硬约束**零回归保护**。新测试给每个用例独立假 `HOME` + 临时安装目录，
   **真的 spawn** `bootstrap/install.mjs`，三个用例：
   A 默认 dry-run ⇒ exit 0、安装目录/DSH 数据目录都没创建、打印了计划；
   B dry-run + `--yes` ⇒ 同样一个文件都没创建（最危险组合：少了 `DRY_RUN` 提前退出，`--yes`
   会把每个 `confirm()` 变成"是"，一路真写下去）；
   C `--apply` 非交互且没给 `--yes` ⇒ 什么都不装、**不许报成功**、说明原因、退出码非 0。
   并已接进 `package.json` 的 `test:unit` 链。
2. **`tests/unit/credentials-write.test.mjs` §7 两条无效断言**：`!import.meta.url.includes(真实凭据路径)`
   恒真（那是本文件自己的路径）；`FIXTURE.includes('FAKE') && !FIXTURE.includes('sk-') === false`
   因 `!` 优先级恒真且语义反了。已换成"读本文件源码、断言不含真实凭据路径字面量"与
   "夹具里每一把 key 都必须带 `FAKE`"。
3. **两份单测里写死的 `3080`** 改为 `import { DEFAULT_PORT }`（`install-health` / `preflight-checks`）
   —— 原来改默认端口不会让任何测试变红。

## 你要重点判断的（这批是测试，所以"假绿"是第一位）

- **这些新断言真的会咬吗？** 逐条问：把被测行为**改坏**，它会不会红？有没有因为 `undefined`、
  空数组、默认值、`||` 短路、`includes` 恒真、正则写错而**恒真**的？有没有断言的是"不等于 true"
  而不是"等于 false"这种弱形态？
- **断言测的是真东西吗？** `install-behavior.test.mjs` 里 spawn 的参数、`HOME`/`DSH_HOME` 注入、
  `stdio`/`input` 的选择，是否真的使它**非交互**、真的把路径指到了临时目录？有没有可能
  在开发机上"碰巧通过"（例如依赖本机已装的 `dsh`、依赖真实端口 3080 上有服务）而在别的机器上
  行为不同？用例 C 的断言是否可能因为提前退出而**没走到**它想断言的那段逻辑？
- **接线**：新测试接进 `test:unit` 的方式对吗？`package.json` 的 diff 有没有把别的东西改坏？
  测试之间的临时目录/环境变量会不会互相污染？
- **硬编码**：还有没有别的"默认值/端口/路径"被逐字写死在测试里，改源码不会让测试变红？
  （注意：与 URL 解析、主机名相关的任意端口号**不算**这类问题。）
- **假的"咬合验证"**：prompt 里声称"删掉 DRY_RUN 提前退出 ⇒ B 会红"，请判断这个说法是否真的成立
  （从代码路径推），以及有没有别的改动会让某个断言**静默失效**。
