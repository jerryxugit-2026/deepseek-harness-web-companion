## 这是什么程序（先看，避免误读）

`dsh-web-companion` = Chrome MV3 扩展 + DSH（DeepSeek Harness）进程内插件的组合。
插件跑在 **DSH 进程内部**，靠用户在 `~/.dsh/profiles/web/cordis.patch.yml` 里的一行被挂载。

**本次审查对象是 `bootstrap/lib/` 里负责"探测环境 + 把各种线接上"的那几个模块**（片 1 审编排入口、
片 3 审交互与判定，都不在你的范围内）。它们负责：

- 算出所有落地路径（安装目录、DSH 数据目录、插件目录、扩展产物目录、Chrome 的清单目录）
- 找到已安装 DSH 的包根，并把插件运行期依赖**符号链接**过去（插件跑在 DSH 进程里，必须与 DSH 用**同一份**子包）
- 生成/推导 Chrome 扩展 ID（由 `manifest.key` 的公钥决定；`a`–`p` 十六进制映射）
- 写 Chrome native messaging host 清单与拉起脚本
- 把插件挂载块**插进/移出**用户的 `cordis.patch.yml`（只碰我们自己那一块，改前备份）
- 把 DeepSeek API key 写进 `~/.dsh/.credentials.yaml` 的 `refs.DEEPSEEK_API_KEY`（**只改这一行**）
- 一个最小的 YAML 标量转义器

用户对它的硬约束：**发行包不含 `node_modules`/`dist`**（依赖一律由引导程序处理）；
**只考虑 macOS**（Windows 可以不做，但不许假装成功）；**每一处会动磁盘的动作都要先经用户确认**；
**默认 dry-run 时一个字节都不许动**。

## 你要找什么（按优先级）

### A. 接线问题（本片重点）

- **生产者和消费者对得上吗**：某函数返回的字段名，调用方是不是按另一个名字读？某处读 `plan.available`、
  另一处写 `plan.ok` 这类不一致；按字符串枚举比较而两端拼写不同（下划线/连字符）；数字与字符串混用。
- **只在一个方向上成立的逻辑**：`upsertCompanion`（插入挂载块）与 `removeCompanion`（移除）是否严格对称？
  插入用的开始/结束标记与移除匹配的是不是同一对？重复插入会不会产生**两块**（或嵌套）？
  用户**手改过**这个文件时会怎样？备份是"每次跑都覆盖上一次的备份"吗（那样第一次的原始状态就丢了）？
- **路径拼接**：`join`/`resolve` 用错地方、把相对路径当绝对路径、符号链接被 `resolve` 追穿之后做比较（会误判"同一个文件"）；
  同一路径在两处以不同写法各拼一遍（漂移风险）。
- **Chrome 侧**：native messaging 清单的 `path` / `allowed_origins` / `type` / 名字，与扩展 `manifest.json`
  里声明的权限/主机是否严格对应？占位符替换有没有漏掉某个（替换失败会写出一个语法合法但永远连不上的清单）？
  扩展 ID 的推导（公钥 → sha256 → 取前 16 字节 → 每个 nibble 映射 `a`–`p`）与 Chrome 的真实规则是否一致？
  有没有把"算出来的 ID"和"Chrome 里真实的 ID"做**校验闸门**（还是只打印一句就当真）？
- **依赖链接**：找不到目标时返回什么？调用方把它当成功还是失败？链接**目标**是文件还是目录、`symlink` 类型参数对不对？
  重复跑（先 `rm -rf` 再建）会不会在失败时留下"空 node_modules 但看起来已装"的状态？
- **凭据写入**：注释承诺"只改这一行、别的逐字节不动"——代码真的做到了吗（是行级替换还是整文件重写）？
  转义（`yaml-scalar`）在含引号、`#`、冒号、换行、`$`、前导 `*`/`&`/`!` 的 key 上是否安全？写坏了会不会让用户的凭据文件整体不可读？

### B. 硬编码

默认端口 / 默认目录 / 包名 / Chrome 配置路径 / native host 名 / `a`–`p` 字母表 / 各平台分支的路径 ——
哪些被写死在多处且不一致？哪些应该来自单一真源？mac 与 linux 分支里有没有复制粘贴导致的漂移
（例如两个分支条件写反、某个分支根本不成立）？

### C. 假绿问题（连着测试一起看）

- 测试是否**真的在测被测对象**：IO 被全部注入成 mock 之后，测的是不是只剩 mock 自己的行为？
  有没有断言可能因为空数组 / `undefined` / 默认值而**恒真**？有没有 `assert(x === x)` 这类空断言？
- 有没有"把期望值改成实现的当前值"（为了绿灯改期望）？错误分支（抛异常、返回 null、目标不存在）有没有被覆盖？
- 测试之间会不会**互相污染**（共享临时目录、共享端口、顺序相关、依赖真实 home 目录）？
- 有没有测试**绕过了真实入口**（只测 lib 函数，而 `install.mjs` 里那段真正的接线从没被测过）——
  如果有，明确指出"哪些行为因此完全没有回归保护"。

### D. 破坏性风险

这个程序的输入是**用户的真实机器**（真实 home、真实 DSH profile、真实凭据文件）。
找出任何"参数算错就会删掉用户东西"的路径（`rmSync` 的目标是怎么算出来的？有没有可能算成 `/` 或 home？），
以及所有写用户文件的地方是否都先备份、备份路径是否可预测、失败时会不会留下半截文件。
